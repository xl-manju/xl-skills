# プロンプト名
> 素人でもこれを見ただけで分かるこのプロンプトを命名
- 帰納的思考プロンプト

# プロンプトの想定利用者
> このプロンプトを実際に使う人物像や役割
- 思考力を高めたい一般ユーザー（不特定多数）

# プロンプト作成の目的
> このプロンプトを作ることで達成したい最終ゴール
- 具体的な事象から共通点を見出し、普遍的な一般論を導き出す帰納的思考を体系的に実践できるようにする

# プロンプト作成の背景
> なぜこのプロンプトが必要になったのか、その経緯や状況
- 思考法図鑑シリーズの一部として、帰納的思考を網羅的にカバーするプロンプトが必要。個別事例からパターンを見出し一般的結論を導く思考法を、誰でも使えるようにしたい。演繹的思考・アブダクションとの関係性も含めた体系的理解を提供する。

# 完了条件（成功基準）
> どのような状態になれば「このプロンプトは完成した」と判断できるか
- ユーザーが任意のテーマで帰納的思考を段階的に実行でき、具体的な事例から妥当な一般論を導き出せること

# 目的達成のための手順
> プロンプトを使用する際の大まかな流れやステップ
1. テーマ設定：分析対象となるテーマ・領域を明確にする
2. サンプル収集：具体的な事象・事例を観察し情報を収集する（多いほど結論の妥当性が高まる）
3. 共通点の抽出：収集した情報の中からパターン・共通点を探し出す
4. 一般化・結論の導出：共通点から普遍的な一般論を結論として導き出す
5. 妥当性検証：反例の探索、過度な一般化のチェック、結論の修正を行う
6. 演繹的展開：導き出した一般論を演繹的に展開し、新たな予測・仮説を立てる

# 解決すべき課題
> プロンプトが解消するべき問題点や現状の不便
- 限られたサンプルからの過度な一般化（早まった一般化の誤り）
- 確証バイアスによる都合の良い共通点のみの抽出
- 反例出現時の結論修正の判断基準が曖昧になりやすい
- 帰納的推論は結論の確実性が保証されない（蓋然的推論）
- サンプルの代表性・偏りの評価が困難

# 目的を達成するために必要な情報
> プロンプトが高品質な出力を行うために、事前に準備・入力しておくべき具体的な情報。
- 分析対象のテーマ・領域
- 観察した具体的な事象・事例（3つ以上推奨）
- 各事象の詳細な特徴・属性
- 分析の目的（何を明らかにしたいか）

# 注意点・制約条件
> プロンプト設計時に守るべき条件や避けたい出力
- 各ステップ毎に成果物を出力して、ユーザーに確認する
- 帰納的推論の限界を明示すること（確実性は保証されない）
- 反例チェックのステップを省略しないこと
- サンプル数と結論の信頼度の関係を意識させること
- 演繹的思考・アブダクションとの関係性を含めること
- 専門知識不要で誰でも使えるようにすること

# プロンプトに対する課題
- 帰納的思考は思考する側の想像力・知識・経験に依存するため、プロンプトでその補助をどこまでできるかが課題

# 想定するユーザー入力1
```
テーマ：飲食店のサービス品質。3つの飲食店で「注文から提供まで10分以内」「スタッフが笑顔」「メニューに写真がある」という共通点を観察した。
```

# 期待される出力1
```
共通点から「顧客満足度の高い飲食店はスピード・接客態度・情報提供の3要素を重視している」という一般論を導出し、反例（高級店は提供速度を重視しない等）を検討した上で結論を修正する。
```

# 想定するユーザー入力2
```
テーマ：商品戦略。ラインナップが乏しい、パッケージに特徴がない、ネーミングが分かりづらいという3つの問題を観察した。
```

# 期待される出力2
```
3つの問題の共通点から「商品戦略全体に問題がある」という一般論を導き、さらに商品の機能やデザインにも問題がないか演繹的に検討する。
```
