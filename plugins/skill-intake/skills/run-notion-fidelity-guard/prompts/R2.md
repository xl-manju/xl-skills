## Layer 1: 基本定義層 (不変原則)

### 1.1 不変ルール
- Notion API を一切叩かず、JSON 構造比較のみで判定する。
- 12 section 全件で `granularity_score` を算出する (途中 break 禁止)。
- verdict=fail 時は即 exit 2 (fail-fast)、後続フェーズに進ませない。

### 1.2 倫理ガード
- 入力 JSON 内の PII フィールドはレポートに転記しない (key のみ列挙)。

## Layer 2: ドメイン層 (本質ロジック)

### 2.1 責務 (Single Responsibility)
- 担当: section 単位の char / field / viz 比較、加重平均と verdict 判定、JSON レポート出力。
- 非担当: Notion API 呼び出し、intake 内容の意味判定 (aggregator 責務)、Markdown 整形 (R3 責務)、canonical 派生 (R1 責務)。

### 2.2 ドメインルール

| 用語 | 定義 |
|---|---|
| `granularity_score` | section 単位の粒度一致度 (0.0-1.0)。`0.30*char_score + 0.40*field_score + 0.30*viz_score`。 |
| `char_score` | 本文文字数が canonical `[min,max]` 内なら 1.0、外なら境界からの乖離率で線形減衰。 |
| `field_score` | canonical `required_fields[]` のうち context に存在し型整合する比率。 |
| `viz_score` | canonical `viz_slots[mandatory=true]` のうち context.figures に対応 slot が存在する比率。 |
| `verdict` | `pass(overall≥0.85) / warn(overall≥0.70) / fail(<0.70)`。 |
| `overall_score` | 12 section の granularity_score 加重平均 (`weight=section.weight`、未指定は 1.0)。 |

ビジネスルール:
- `absence_behavior=block` の section が完全欠落 → 即 verdict=fail。
- `absence_behavior=warn` の section が欠落 → granularity_score=0.0 として算入。
- 閾値 (`fidelity_threshold_pass`, `fidelity_threshold_warn`) は CLI 引数で上書き可能。

### 2.3 入力契約

| field | type | required | 説明 |
|---|---|---|---|
| context-json (positional) | path | yes | `intake-final-context.json` |
| --pass-threshold | float | no | 既定 0.85 |
| --warn-threshold | float | no | 既定 0.70 |

### 2.4 出力契約
- schema: `schemas/fidelity-report.schema.json` (additionalProperties:false)
- 必須フィールド: `schema_version`, `context_path`, `canonical_sha256`, `overall_score`, `verdict`, `sections[]`, `blockers[]`

## Layer 4: 共通ポリシー層

### 4.1 失敗時挙動
- exit: 0=pass / 1=warn / 2=fail / 3=入力エラー。
- 入力 JSON parse エラー → exit 3、stderr に `[R2] invalid input: <reason>`、レポート未生成。
- canonical-page-snapshot.json 不在 → exit 3、`R1 を先に実行せよ` を stderr。
- 自己検査 (E1/E4) 違反 → exit 3、`eval-log/r2-self-check-fail-<ts>.json` を残す。

### 4.2 観測 / ロギング
- verdict=fail → `eval-log/fidelity-fail-<timestamp>.json` に append、skill-intake-handoff へ差し戻し。
- verdict=warn → 公開許可、`warnings[]` を CI ログへ伝播。

### 4.3 セキュリティ
- PII フィールドはレポートに転記しない (key のみ列挙)。

## Layer 5: エージェント層 (実行主体定義)

### 5.1 担当 agent
- `@fidelity-checker` (決定論バッチ、対話禁止)
- 実体: `scripts/validate-notion-fidelity.py`

### 5.2 推論手順 (再現可能)
1. `canonical-page-snapshot.json` をロード (sha256 を保持)。
2. `intake-final-context.json` をロードし、`section_key → §id` マッピングを `references/section-key-mapping.json` で解決。
3. 各 section について:
   - `char_score` = `score_char(section_text_length(text), bounds)`
   - `field_score` = `len(present_fields ∩ required) / len(required)`
   - `viz_score` = `len(present_viz ∩ mandatory_slots) / len(mandatory_slots)` (mandatory_slots が空なら 1.0)
   - `granularity_score = 0.30*char_score + 0.40*field_score + 0.30*viz_score`
4. `block` 違反検査: `absence_behavior=block` の section が missing なら即 verdict=fail (overall は計算継続)。
5. `overall_score = weighted_average(sections[].granularity_score)` を算出。
6. verdict を閾値で確定し、`fidelity-report.json` を atomic write。
7. exit code を verdict に応じて返却。

### 5.3 自己検証 checklist
- [ ] E1: `len(report.sections) == 12`
- [ ] E2: `report.verdict in {pass, warn, fail}`
- [ ] E3: exit code が verdict と 1:1 (`pass=0 / warn=1 / fail=2`)
- [ ] E4: `report.blockers != []` なら verdict は必ず `fail`
- [ ] E5: 同一 (context, canonical) で連続 2 回実行が bit-identical
- [ ] E6: 全 section の `granularity_score ∈ [0.0, 1.0]`
