# Elegant Review Protocol

30思考法を 4 検証条件 × 3 フェーズに圧縮した品質レビュー手順。新規スキル作成、大規模リファクタ、publish 前ゲートで適用し、思考の俯瞰 → 並列分析 → 改善実行をこの順で実行する。skill-intake と skill-creator の両方から参照される共通プロトコル。

## 4 検証条件

- **C1 矛盾なし**: 同一対象に対する記述・制約・期待値が衝突しない。
- **C2 漏れなし**: 必須要素・必須セクション・必須ハンドオフが全て埋まっている。
- **C3 整合性**: 用語・粒度・命名・参照パスが規約と一致する。
- **C4 依存関係**: 前提・順序・参照先が存在し循環しない。

## 3 フェーズプロトコル

### Phase 1: 思考リセット・俯瞰 (read-only)
- 対象成果物を一切編集せず全体を読み、構造・意図・前提を再構成する。
- メタ認知・第一原理・リフレーミングで暗黙前提を露出させる。
- 出力: 俯瞰レポート（対象範囲 / 目的 / 既知の制約 / 直感的懸念）。

### Phase 2: 並列分析
3 系統を並列実行し、4 条件 × 思考法のマトリクスで所見を記録する。
- 論理構造（9 思考法）: C1/C2 を中心に MECE・反証・因果で抜け矛盾を抽出。
- メタ発想（9 思考法）: C3 を中心に抽象化・リフレーミングで規約一致を検査。
- システム戦略（12 思考法）: C4 を中心に依存・ボトルネック・リスクで構造健全性を評価。
- 出力: `{C1..C4} × {思考法}` の所見表（指摘事項・該当箇所・改善方針）。

### Phase 3: 改善実行
- 所見を依存関係でグルーピングし、独立対象は並列、依存ありは直列で適用。
- 各改善後に該当条件 (C1〜C4) を再検証し、副作用が出た場合は Phase 2 へ戻る。
- 出力: 変更パス、検証コマンド、残リスク。

## ゲート条件

- **Phase 1 完了**: 俯瞰レポートが対象範囲・目的・懸念を網羅、編集ゼロ。
- **Phase 2 完了**: 4 条件すべてに所見表が存在し、空欄・未検証なし。
- **Phase 3 完了**: 全所見が「適用済」「却下＋理由」「保留＋次アクション」のいずれかに確定。
- 先送り禁止: 「後で対応」は不可。保留にする場合も次アクションと期限を明記する。

## 適用タイミング

- **新規スキル作成時**: SKILL.md 初稿確定後、references 整備前に Phase 1〜2 を実施。
- **大規模リファクタ**: 構造変更前後で Phase 1〜3 を完走。
- **publish 前ゲート**: マニフェスト確定後、必須 4 条件の最終チェックとして全フェーズ実行。

## 圧縮原則

- プロンプト本体に思考法の解説文を埋め込まない。本 reference を参照する。
- 各思考法は「名称 + 1 行用途」のみ。長文解説は禁止。
- 所見表・俯瞰レポートはテンプレート化し、自由記述を最小化する。
- 重複した観点（例: MECE と構造化）は一方に統合してよい。網羅性より重複排除を優先。
