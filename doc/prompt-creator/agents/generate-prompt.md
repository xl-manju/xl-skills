Prompt作成シートの全項目を読み取り、ユーザーが選択したフォーマット

Prompt作成シートの情報を漏れなく7層構造に配置し、

## 4. 実行仕様

### 4.1 思考プロセス（Layer単位生成 + 多段階検証）

> **核心原則1**: LLMの成果物は小分けして出力するほうが精度が高い。
> 7層を一括生成せず、1Layerずつ生成→合算→複数回検証で漏れを防止する。
>
> **核心原則2**: 要素（フィールド・文章）は短く原子的に記述するほど精度が高い。
> 1要素が長文になると理解精度が低下する。各値は1概念=1短文で表現する。
>
> **核心原則5（記述スタイル）**: すべてのルール・制約・指示には「ルール本体 + 目的 + 背景」をセットで併記する。
> 細部の手順を冗長列挙せず、概念・概要・大まかな流れに留め、細部の判断は実行時のLLMに委ねる。
> 出力フォーマットの既定は Markdown。
> 詳細: [references/writing-style-principles.md](../references/writing-style-principles.md)

#### Phase 4-A: Layer単位生成

| ステップ | アクション                                        | 担当   | 出力先 |
| -------- | ------------------------------------------------- | ------ | ------ |
| A-1      | scaffold_prompt.jsで7層骨格を決定論的生成         | Script | tmp/   |
| A-2      | Layer 1: 基本定義（目的・背景・成功基準）を充填   | LLM    | tmp/layer1.yaml |
| A-3      | Layer 2: ドメイン定義（ユビキタス言語・ルール）を充填 | LLM | tmp/layer2.yaml |
| A-4      | Layer 3: インフラストラクチャ（ツール・ACL）を充填 | LLM   | tmp/layer3.yaml |
| A-5      | Layer 4: 共通ポリシー（制約・品質基準・**出力評価基準**）を充填 | LLM | tmp/layer4.yaml |
| A-6      | Layer 5: エージェント定義（Bounded Context単位）を充填 | LLM | tmp/layer5.yaml |
| A-7      | Layer 6: オーケストレーション設計（**自己評価・改善ループ**含む）を充填 | LLM | tmp/layer6.yaml |
| A-8      | Layer 7: ユーザーインタラクション設計を充填       | LLM    | tmp/layer7.yaml |
| A-9      | merge_layers.jsで7ファイルを合算                  | Script | merged.yaml |

> 各Layer生成時、LLMはヒアリングJSONとマッピングテーブルを参照し、
> そのLayerに対応する全項目を漏れなく反映する。

#### Phase 4-B: 4パスパイプライン検証（1パス=1観点）

> **核心原則4**: 1パス=1観点に集中。全観点を1回でチェックせず、順番に検証→修正→次へ進む。

| ステップ | アクション                                          | 担当   | 観点 |
| -------- | --------------------------------------------------- | ------ | ---- |
| B-1      | validate_prompt.jsで7層構造検証                     | Script | 構造 |
| B-1.5    | Pass 0: `evaluation_priorities`から動的評価基準を生成 | LLM  | 動的基準 |
| B-2      | Pass 1: 網羅性チェック（+ derivation_log反映確認）  | LLM    | 網羅 |
| B-3      | Pass 2: 整合性チェック（データフロー・Layer間矛盾） | LLM    | 整合 |
| B-4      | Pass 3: 深度チェック（実行可能粒度・検証可能性）   | LLM    | 深度 |
| B-5      | Pass 4: 実用性チェック（初回ユーザー視点）         | LLM    | 実用 |
| B-6      | 全Pass PASS → Phase 4-C へ / NG → 該当Pass修正後再実行 | 判定 | Gate |

📖 詳細: [agents/review-prompt.md](review-prompt.md)

#### Phase 4-C: AI自律評価・改善

> **目的**: 4パス検証後、AIが `evaluation_priorities` に基づき自己評価を行い、不足があれば自律的に修正する。
> **ユーザー介入不要**: 評価・改善はAIが自律実行し、結果のみ最終報告に含める。

| ステップ | アクション                                        | 担当   |
| -------- | ------------------------------------------------- | ------ |
| C-1      | `evaluation_priorities` に基づくAI自己評価を実行  | LLM    |
| C-2      | 不合格項目の修正種別を判定（下記参照）            | LLM    |
| C-3      | 修正実行 → 再評価（最大3回まで反復）              | LLM    |
| C-4      | 全項目合格 or 最大回数到達 → Phase 4-D へ         | Gate   |

##### 修正時の戻り先判断基準

| 修正の種類 | 戻り先 | 理由 |
|-----------|--------|------|
| 内容の追加・変更（Layerの中身を書き換え） | Phase 4-A（該当Layer再生成） | Layer再生成が必要 |
| 品質の改善（表現の曖昧さ、整合性の問題） | Phase 4-B（該当Pass再実行） | 再検証で改善可能 |

##### 評価結果の記録

評価結果は最終報告に含める（ユーザーへの提示用）：

```
## AI自律評価結果
evaluation_priorities: [{{priority_1}}, {{priority_2}}]

| 評価項目 | 結果 | 修正内容（該当時） |
|---------|------|-------------------|
| {{項目名}} | PASS/修正済み | {{修正内容}} |

改善回数: {{N}}回 / 最大3回
```

#### Phase 4-D: フォーマット変換・ファイル出力

| ステップ | アクション                                        | 担当   |
| -------- | ------------------------------------------------- | ------ |
| D-1      | YAML正規形 → 指定フォーマットに変換               | Script |
| D-2      | convert後にvalidate_prompt.jsで再検証             | Script |
| D-3      | 指定パスにファイルを書き出す                      | Write  |
| D-4      | ユーザーに出力完了 + AI評価結果を報告             | LLM    |

### 4.1.1 Layer単位生成のルール

| ルール | 説明 |
| ------ | ---- |
| 1Layer=1出力 | 各Layerを独立したLLM呼び出しで生成する |
| 対応項目の明示 | 各Layer生成時に「このLayerに反映すべき項目」をリスト表示してから生成 |
| 前Layer参照 | Layer N生成時にLayer 1〜(N-1)を参照して整合性を確保 |
| 生成後即検証 | 各Layer生成直後にマッピングテーブルと照合 |
| 要素原子性 | 各フィールド値は1概念=1短文（目安50文字以内）で記述する |
| 長文分割 | 複合的な内容はリスト・テーブル・サブキーに分解する |
| 散文禁止 | key-value、箇条書き、テーブルを優先し、散文的な長文を避ける |
| 省略禁止 | 「以下同様」「省略」は使わず、全項目を書き出す |
| 出力評価基準生成 | Layer 4生成時: `evaluation_priorities` + ドメイン情報から出力評価基準を動的生成（seven-layer-format.md参照） |
| 自己評価ループ生成 | Layer 6生成時: Layer 4の出力評価基準を参照する自己評価・改善ループを含める |

| Prompt作成シート項目         | 7層構造の配置先                           |
| ---------------------------- | ----------------------------------------- |
| プロンプト名                 | Layer 1: メタ情報 > プロジェクトID        |
| 目的                         | Layer 1: 最上位目的                       |
| 背景                         | Layer 1: 背景コンテキスト                 |
| 完了条件                     | Layer 1: 成功基準                         |
| 想定利用者                   | Layer 1: プロジェクト概要 / Layer 7: 初回質問設計 |
| 手順の中の専門用語           | Layer 2: 用語集                           |
| 手順の制約・ルール           | Layer 2: ビジネスルール                   |
| 解決すべき課題               | Layer 2: ビジネスルール / Layer 4: 品質基準 |
| 出力で使うツール・外部連携   | Layer 3: ツール定義                       |
| 注意点・制約条件             | Layer 4: 共通ポリシー（セキュリティ/品質）|
| プロンプトに対する課題       | Layer 4: 品質基準（設計課題として参照）   |
| 手順のステップ               | Layer 5: エージェント定義（思考プロセス） |
| 出力フォーマット             | Layer 5: エージェント出力テンプレート     |
| 全体フロー                   | Layer 6: オーケストレーション             |
| 想定入力例                   | Layer 7: ユーザーインタラクション         |
| 必要な情報                   | Layer 7: 初回質問の設計材料               |
| evaluation_priorities        | Layer 4: 出力評価基準（動的評価項目の生成材料） |
| derivation_log               | Layer 1: メタ情報（設計判断の追跡記録）   |

### 4.3 チェックリスト

| 項目                                           | 基準                                         |
| ---------------------------------------------- | -------------------------------------------- |
| Layer 1〜7がすべて含まれているか               | 7つのLayer全てが出力に存在                   |
| Prompt作成シートの全項目が反映されているか     | マッピングテーブルの全行が対応               |
| `{{}}`変数が適切に配置されているか             | 可変部分は全て変数化                         |
| エージェント間の依存関係に矛盾がないか         | 循環依存なし、全入力に提供元あり             |
| 出力テンプレートが各エージェントに定義されているか | Layer 5の全エージェントに出力テンプレート存在 |
| コメント・セパレータが`#`で統一されているか    | `====`や`---`は使用していない                |
| 説明文がプロンプト本文に含まれていないか       | 成果物のプロンプトのみ                       |
| 各情報が簡潔でシンプルな一意な表現か           | 冗長表現なし                                 |
| 各フィールド値が1概念=1短文（50文字以内）か    | 長文の値がない、散文的記述がない             |
| 複合内容がリスト・テーブル・サブキーに分解されているか | 1つの値に複数概念が混在していない       |
| Layer 4に出力評価基準が含まれているか     | evaluation_prioritiesから動的生成された評価項目が存在 |
| Layer 6に自己評価・改善ループが含まれているか | Layer 4の出力評価基準を参照するループが存在 |

### 4.4 ビジネスルール（制約）

| 制約                 | 説明                                                       |
| -------------------- | ---------------------------------------------------------- |
| フォーマット厳守     | ユーザー選択のフォーマット（YAML/MD/JSON/XML）で出力       |
| 変数テンプレート必須 | 全ての可変部分を`{{}}`で囲む                               |
| コメント統一         | `#`コメントアウトのみ使用                                  |
| 依存関係の柔軟性     | 直列・並列・ループ・条件分岐に対応できる設計               |
| プロンプトのみ出力   | 説明文・ヘッダ装飾（`====`）は含めない                     |
| 要素原子性           | 1フィールド=1概念、1値=1短文（50文字以内目安）。長文はリスト・サブキーに分解 |

### 4.5 意味的深度ルール（質ベース判定）

> **核心原則3**: 構造的に正しいだけでは不十分。各Layerが意味的に十分な深度を持つこと。
> 数量（「3つ以上」「4つ以上」）ではなく、**質**（「実行可能か」「検証可能か」）で判定する。

| # | ルール | 対象Layer | 質的判定質問 |
|----|--------|-----------|--------------|
| D-1 | **ステップは実行可能粒度** | Layer 5 | 各ステップを読んで「次に何をすべきか」迷わないか？追加質問なしで着手できるか？ |
| D-2 | **知識ベースの統合** | Layer 5 | 参考文献の概念・手法が「どのステップで」「どう使うか」具体的に分かるか？ |
| D-3 | **評価基準の識別可能性** | Layer 2 | 評価基準の各レベルを読んで「どのレベルに該当するか」客観的に判断できるか？ |
| D-4 | **遷移の検証可能性** | Layer 6 | 「このフェーズは完了した」「次に何を渡すか」を第三者が検証できるか？ |
| D-5 | **回答例のパターンカバレッジ** | Layer 7 | 回答例を見て「自分のケースに当てはめるヒント」が得られるか？典型・境界・例外をカバーしているか？ |
| D-6 | **出力の追跡可能性** | Layer 5 | 出力を見て「なぜこの結果になったか」「どこまで有効か」遡って分かるか？ |
| D-7 | **用語の関係性** | Layer 2 | 用語が孤立せず、関連概念とのつながりが理解できるか？ |

#### Layer別深度チェックポイント（質ベース）

**Layer 2（ドメイン定義）:**
- 用語集: 各用語の定義を読んで「この言葉をどう使うか」迷わないか？
- 評価基準: 各レベルの境界が明確で、客観的に識別できるか？
- ビジネスルール: 制約を読んで「これは許可されるか」即座に判断できるか？

**Layer 5（エージェント定義）:**
- 思考プロセス: 各ステップを読んで「次に何をすべきか」迷わないか？
- 判断基準: 完了条件を読んで「達成したかどうか」第三者が検証できるか？
- 出力テンプレート: 結果を見て「なぜこうなったか」「どこまで有効か」分かるか？

**Layer 6（オーケストレーション）:**
- 完了条件: 「このフェーズは完了した」を客観的に判断できるか？
- 引き渡しデータ: 次フェーズが「何を受け取るか」事前に分かるか？
- 確認ポイント: 「ここで確認しないと手戻りリスクが高い」箇所に設定されているか？

**Layer 7（ユーザーインタラクション）:**
- 回答例: 典型・境界・例外のパターンをカバーしているか？
- 応用性: 例を見て「自分のケースにどう当てはめるか」ヒントが得られるか？
- 難易度: 初心者〜上級者まで参考になる例があるか？

### 4.6 フォーマット別生成ルール

| フォーマット | 変換ルール                                       |
| ------------ | ------------------------------------------------ |
| YAML         | seven-layer-format.md の構造に従う、2スペースインデント |
| Markdown     | `#` 見出しでLayer表現、テーブルとコードブロック活用    |
| JSON         | 日本語キー、ネストで7層表現、配列でリスト              |
| XML          | 英語タグ（layer1〜7）、属性で日本語名、CDATAで長文     |

### 4.7 エージェント設計ガイド

| パターン   | 条件                     | Layer 5の構造                    |
| ---------- | ------------------------ | -------------------------------- |
| 単一       | エージェント数=1         | エージェント1つのみ定義          |
| 複数直列   | 順序依存あり             | 前提→後続の依存関係を明示        |
| 複数並列   | 独立タスクあり           | 並列実行可能なエージェントを定義 |
| ループ     | 品質基準による反復       | 完了判定と再選択ロジック         |
| 条件分岐   | 入力条件でパス分岐       | conditions in オーケストレーション|
